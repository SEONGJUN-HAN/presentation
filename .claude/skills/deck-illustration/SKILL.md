# 덱 그림 기획 → 생성(안티그래비티) → 배치

그림은 **Claude 가 직접 그리지 않는다** (SVG 삽화 금지 — 품질이 나빠 사용자가 거부함).
사용자가 안티그래비티에서 나노바나나로 생성하고, Claude 는 **기획·프롬프트·배치·검증**만 한다.

두 단계로 나뉜다. 요청이 어느 쪽인지 보고 해당 단계만 한다.

- **A. 기획** — "그림 기획해줘", "그림 넣어줘" (아직 그림 없음)
- **B. 배치** — "그림 만들었어", "배치해줘" (`img/<덱>/` 에 png 가 생김)

---

## A. 기획

### 1. 덱을 읽고 장마다 "할 일"로 판단

`slides/<덱>/*.html` 을 전부 읽는다.

> **먼저 덱이 슬라이드키트인지 본다.** 루트가 `<div class="sk ...">` 가 아니라
> `section-cover` · `title-cover` · `slide-title` + `content-area` 이면 옛 방식 덱이다.
> 아래 배치 방식(`sk--photo`, `shot`, `card--row`)은 슬라이드키트에서만 동작하므로
> 사용자에게 먼저 묻는다 — ① 그림 넣을 장만 슬라이드키트로 바꾸기, ② 계속 쓸 덱이면 덱 전체 전환.
> 전체 전환은 문구는 그대로 두고 구조만 바꾸며, 묶음마다 넘침 검사 후 커밋한다.
> (본보기: `slides/AI업무자동화_연수/` — 2026-10 전체 전환)

각 장을 아래 셋 중 하나로 분류한다.

| 그 장이 하는 일 | 그림 | 배치 방식 |
|---|---|---|
| **느낌·공감** (표지, 섹션 표지, "왜?", 목표, 마무리) | 넣음 | 흐린 배경 `sk--photo` · 16:9 |
| **비유로 설명** (섬, 미로, 다리, 길…) | 넣음 | 옆에 크게 `shot` · 4:3 |
| **읽고 따라 하기** (절차, 메뉴 위치, 코드, 숫자표) | **넣지 않음** | 글씨 + 실제 화면 캡처 |

- 한 덱에 **4~8장**. 전부 넣으면 강조가 사라진다.
- 실습·절차 장에는 그림 대신 **실제 화면 캡처**를 사용자에게 요청한다.
- 같은 비유가 두 장에 걸치면(예: 끊어진 섬 → 이어진 섬) **같은 소재로 이어지게** 기획한다. 덱 전체에 흐름이 생긴다.

#### 흐린 배경 장은 "주인공"을 정하고 좌우로 나눈다

그림과 글씨를 **둘 다 가운데**에 두면 초점이 한 점에 겹쳐 그림을 많이 죽여야 글씨가 읽힌다.
초점을 좌우로 나누면 그림을 0.8까지 밝게 살리고도 글씨가 읽힌다. (사용자 원칙, 2026-10)

| 이 장의 주인공 | 클래스 | 그림 | 글씨 | 프롬프트 구도 |
|---|---|---|---|---|
| **그림** (비유가 핵심인 표지) | `sk--photo-left` | 왼쪽 — 눈이 먼저 닿음 | 오른쪽 | 소재는 **왼쪽 60%**, 오른쪽 40% 빈 검정, 인물은 **오른쪽을 바라보게** |
| **글씨** (메시지가 핵심, 그림은 분위기) | `sk--photo-right` | 오른쪽 — 보조 | 왼쪽 | 소재는 **오른쪽 60%**, 왼쪽 40% 빈 검정, 인물은 **왼쪽을 바라보게** |

| 소재가 아래에 몰린 그림 / 위에 몰린 그림 | `sk--photo-bottom` / `sk--photo-top` | 아래 / 위 | 위 / 아래 | 소재는 **아래 60%**(또는 위), 반대쪽 40% 빈 검정 |

- **위아래도 같은 원리**다 (사용자 지적, 2026-10-15). 소재가 화면 폭 전체에 퍼져 있으면 좌우로 나눌 때 한쪽이 글씨 밑에 깔린다 — 이럴 땐 위아래로 나눈다 (교데통 01·07 허브/섬).
- 이미 있는 그림은 **좌우·위아래를 둘 다 캡처해 보고** 소재가 덜 가려지는 쪽을 고른다.
- 근거: 왼쪽 위부터 읽는 시선(Z 패턴) · 비대칭 균형과 여백(삼분할) · 어둡게 하는 건 글씨 쪽만(가로 그라데이션) · 인물의 시선이 글씨를 향하면 눈이 글씨로 흐른다.
- 가운데 배치(`sk--photo` 만)는 **소재가 추상적이고 글이 아주 짧을 때만**. 기본은 좌우 분리.
- 본문(카드·코드가 많은 장)은 좌우를 나눌 자리가 없다 — 흐린 배경을 아주 어둡게(0.3) 쓰거나 그림을 빼고 `shot` 으로.

### 2. 사용자에게 기획표를 먼저 보여 준다

| 파일 | 슬라이드 | 장면 | 방식 | 주인공·구도 |
|---|---|---|---|---|

확인을 받은 뒤 3으로 간다. (기획이 이미 합의된 상태면 바로 3)

### 3. `img/<덱>/프롬프트.md` 작성

[prompt-template.md](prompt-template.md) 를 복사해서 채운다. 원칙:

- **파일명** `NN_영문.png` — NN 은 슬라이드 번호 (예: `05_islands.png`). 슬라이드 번호가 바뀌면 파일명도 같이 바꾼다.
- **프롬프트는 영어**, 설명·안내는 한국어.
- **[공통 스타일]** 은 덱 테마에서 가져온다. 기본은 검정 배경 + 앰버(#fbbf24) 하나, 아이소메트릭 3D 클레이. 덱에 `[data-deck]` 테마 오버라이드가 있으면 그 색으로 바꾼다.
- **그림 안에 글자·숫자·로고 금지** — 한글이 깨진다. 글씨는 HTML 로 얹는다.
- **1번을 먼저 만들고 나머지는 1번을 스타일 참조**로 넘기라고 적는다.
- **구도**
  - 흐린 배경용(16:9): **주인공에 따라 소재를 왼쪽 60% 또는 오른쪽 60% 안에**, 반대쪽 40%는 "completely empty pure black". 인물은 빈 쪽을 바라보게. (위 표)
    **배경은 화면 전체가 이어진 순수한 검정, 바닥·벽·회색 배경 금지**도 꼭 적는다 — 빼면 빈 쪽만 검게 칠하고 소재 쪽엔 회색 바닥을 깔아 세로 경계선이 생긴다 (04번 실패).
    **배경은 화면 전체가 이어진 순수한 검정, 바닥·벽·회색 배경 금지**도 꼭 적는다 — 빼면 빈 쪽만 검게 칠하고 소재 쪽은 회색 바닥을 깔아 세로 경계선이 생긴다.
  - ❌ "소재를 가운데에" — 1차(AI업무자동화)에서 글씨를 옆에 두자 소재 절반이 글씨 밑에 깔려 4장을 다시 만들었다.
  - 옆에 두는 그림(4:3): 소재가 프레임을 채우게.
  - ❌ "위쪽 55%를 비우고 소재는 아래" 구도 금지 — 제목이 위로 밀려 작아져서 실패했다.
- 사람은 **faceless stylized figure** 로.

마지막에 사용자에게 안티그래비티에 붙여 넣을 한 줄을 준다.

```
img/<덱>/프롬프트.md 를 읽고 그대로 이미지 만들어서 저장해줘
```

## B. 배치

### 1. 그림을 전부 본다

`img/<덱>/*.png` 를 Read 로 하나씩 열어 확인한다. 글자가 들어갔거나 화풍이 튀면 그 파일만 다시 만들어 달라고 한다.

- **오른쪽 아래 제미나이 별(✦) 워터마크**가 찍혀 오는 그림이 있다. 검은 배경 위면 주변 색으로 칠하고, 소재 위에 겹치면 그 귀퉁이를 잘라 낸다 (PIL). 원본은 scratchpad 에 백업.
- **파일이 2MB 넘으면 줄인다** — 16:9 는 1376×768, 4:3 은 1600×1200. build.js 가 base64 로 넣어 덱 파일이 커진다.

### 2. 슬라이드에 넣는다

**흐린 배경 표지** — 주인공에 따라 `sk--photo-left`(그림 왼쪽) 또는 `sk--photo-right`(그림 오른쪽)를 함께 붙인다
```html
<div class="sk sk-cover sk--photo sk--photo-left tone-amber">
  <img class="sk-bg" src="img/<덱>/01_cover.png" alt="">
  <div class="sk-cover__label">라벨</div>
  <h1 class="sk-cover__title">제목<br><em>강조</em></h1>
  <p class="sk-cover__desc">문장마다<br>줄바꿈</p>
</div>
```
- 이모지 아이콘(`sk-cover__icon`)과 글로우(`sk-cover__glow`)는 뺀다 — 그림이 그 역할.
- 제목은 두 줄이 좋다 (가운데 58px · 좌우 분리 50px — 글씨 칸이 화면 절반이라).
- 그림 가장자리는 **비네트로 흐리게**(가운데 밝고 끝으로 갈수록 어둡게) — 좌우·위아래 분리 배경, 가운데 배경, `shot--fade`(사각형으로 사방 흐림 — 원형은 동그란 창문처럼 보여 버림)에 이미 들어 있다. 딱 끊긴 테두리는 단절감을 준다.
- 이미 가운데 구도로 만든 그림도 좌우 분리를 먼저 시험해 본다 — 그림을 74% 폭으로 한쪽에 붙이고 끝을 페이드하므로 소재가 넓게 퍼진 그림은 그대로 맞는다. 소재가 글씨 밑에 깔리면 그 장만 구도를 지정해 다시 만든다.

**흐린 배경 본문** — 카드는 **`card--row` 로 납작하게** 해서 아래로 모은다. 카드를 크게 쓰면 그림이 다 가려진다.
```html
<div class="sk sk--photo tone-amber">
  <img class="sk-bg" src="img/<덱>/03_worry.png" alt="">
  <div class="s-head">...</div>
  <div class="cols">
    <div class="card card--row">
      <div class="card__icon"><i class="fa-solid fa-..."></i></div>
      <div><div class="card__title">제목</div><div class="card__body">한 줄</div></div>
    </div>
    ...
  </div>
</div>
```

**옆에 크게**
```html
<div class="cols cols--right">          <!-- 그림 쪽이 넓게 -->
  <div class="col"><img class="shot" src="img/<덱>/05_islands.png" alt="설명"></div>
  <div class="col"> card--row 여러 개 </div>
</div>
```

- `src` 는 반드시 `img/` 로 시작 (build.js 가 이 패턴만 base64 로 넣는다).
- slide-kit.css 를 고쳤으면 `index.html` 의 `slide-kit.css?v=` 숫자를 올린다.

### 3. 검증 — 1280×720 실제 크기로

> 미리보기 창이 좁게 열려 있으면 1280×720 에뮬레이션 스크린샷이 귀퉁이에 작게만 찍힌다.
> 그럴 땐 헤드리스 Edge 로 찍는다 (서버는 5599 에 떠 있어야 함):
> `node .claude/skills/deck-illustration/shot.mjs <덱> <scratchpad>/caps 1,4,19` → `caps/01.jpg` … 를 Read.

1. preview 서버(`presentation`)를 띄우고 `resize_window` 1280×720.
2. `?deck=<덱>` 으로 열고 JS 로 장을 옮기며 스크린샷:
   ```js
   currentSlide = N; updateSlideUI();
   ```
   (화살표 키 연타는 전환 애니메이션 중에 찍혀 흐리게 나온다 — 2초 기다린 뒤 찍는다.)
3. 넘침·깨진 그림 검사:
   ```js
   [...document.querySelectorAll('.slide-container .sk')].map((s,i)=>
     (i+1)+':'+s.scrollHeight+'/'+s.clientHeight+'/'+
     [...s.querySelectorAll('img')].map(m=>m.naturalWidth?'ok':'X').join('')).join(' ')
   ```
   모든 장이 `720/720`, 그림은 `ok` 여야 한다.
4. 눈으로 볼 것: 그림의 핵심 소재가 글씨 밑에 깔리지 않았는가 / 그림이 먼저 보이고 글씨로 시선이 넘어가는가 / 본문 배경 그림이 카드에 다 가려지지 않았는가.
5. 끝나면 `resize_window` preset desktop 으로 되돌린다.

### 4. 빌드

```bash
node build.js <덱>
```
`⚠ 이미지 없음` 경고가 없어야 한다.
