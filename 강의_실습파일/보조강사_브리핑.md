# 오토핫키 연수 개편 브리핑 — v1 → v2

> 보조강사용. 예전(v1) 강의를 알고 계신다는 전제로, **왜 바꿨는지**와 **무엇이 달라졌는지**만 정리했습니다.

---

## 한 줄 요약

**언어를 v2로 올리면서, "배우는 부분"과 "바로 쓰는 부분"을 한 파일 안에서 위아래로 갈랐습니다.**
윗부분은 예전처럼 직접 쳐 보며 배우고, 아랫부분은 이해 못 해도 눌러서 바로 써 보는 곳입니다.

---

## 왜 바꿨나

### 1. 새로 배우는 사람에게 v1을 가르치는 건 맞지 않다
- 공식 배포판도, 인터넷 자료도, **AI가 짜주는 코드도 이제 v2 기준**입니다.
- 강사가 v1이 익숙하다는 이유로 v1을 가르치면, 수강생은 집에 가서 AI에게 물었을 때 문법이 안 맞아 막힙니다.
- 실제로 "AI가 옛 버전(v1) 문법을 주는 것"이 바이브코딩 실패 1순위라 슬라이드에서도 경고합니다.

### 2. 지난 강의의 아쉬움 — 교육용과 실전용 사이에 다리가 없었다
- **교육용 예제만으로 하면** 실전성이 떨어지고,
- **강사 실전 런처로 하면** 코드가 복잡해 보여 교육이 힘들었습니다.
- 수강생 입장에서 6단계 실습이 끝나도 강사 런처는 "다른 세계"로 남았습니다.

### 3. 그래서 세운 원칙
- **코딩 안 배운 사람이 직관적으로 이해 못 하는 건 뺀다.** (자세히 설명해서 넘기려 하지 않는다)
- **편하게 쓰려고 어쩔 수 없이 복잡해진 부분은 "AI가 만든 것, 편하려고 넣은 것이니 그냥 넘어간다"고 대놓고 말한다.**
- 이 원칙이 곧 연수의 메시지("모르면 AI에게 맡긴다")와 같아서, 난이도를 낮추는 것과 메시지를 전하는 것이 같은 행동이 됩니다.

## 문법은 무엇이 달라졌나 — 강의에 나오는 것만

바뀐 건 사실상 **두 가지**입니다.

1. **명령어 → 괄호 쓰는 함수**: `Run, 주소` → `Run("주소")`
2. **레이블(점프할 자리) → 이벤트에 직접 연결**: `gRun1` + `Run1:` → `.OnEvent("Click", ...)`

| 하는 일 | v1 | v2 |
|---|---|---|
| 열기 | `Run, https://www.naver.com` | `Run("https://www.naver.com")` |
| 알림창 | `MsgBox, 반갑습니다` | `MsgBox("반갑습니다")` |
| 여러 줄 핫키 | `^!k::` … `return` | `^!k::` `{ … }` |
| 창 만들기 | `Gui, +AlwaysOnTop` | `g_Gui := Gui("+AlwaysOnTop", "제목")` |
| 버튼 붙이기 | `Gui, Add, Button, w260 gRun1, 업무일지` | `b1 := g_Gui.AddButton("w260", "업무일지")` |
| 눌렀을 때 | `Run1:` 레이블로 점프 | `b1.OnEvent("Click", (*) => …)` |
| 창 보이기 / 닫기 | `Gui, Show` / `Gui, Destroy` | `g_Gui.Show()` / `g_Gui.Destroy()` |
| 창 X 누름 | `GuiClose:` 레이블 | `g_Gui.OnEvent("Close", …)` |
| 클립보드 | `Clipboard := "…"` | `A_Clipboard := "…"` |
| 키 보내기 | `Send, ^v` | `Send("^v")` |

- **위치 옵션(`w260`, `h34`, `xm`, `y+10` 등)은 v1과 똑같습니다.** 레이아웃 감각은 그대로 쓰시면 됩니다.
- v1 런처는 버튼마다 레이블을 따로 만들고 그 안에서 `Gui, Destroy` → `Run`을 했습니다. v2에서는 그 두 동작을 **쉼표로 이어 한 줄**에 씁니다.
- GUI 대조를 더 보시려면 → [AutoHotkey GUI 이관 노트](https://claude.ai/code/artifact/b4bdd7bb-fc66-4524-bb48-71706632df3c)

## 실습 파일 구조 — 위아래로 성격이 다릅니다

```
내업무도구.ahk
├─ 윗부분  [0~6단계] + [클릭 1~3단계]   ← 배우는 곳   Ctrl + Alt + L
│    직접 쳐 보며 만든다. 전부 이해하고 넘어간다.
│
└─ 아랫부분 [7~11단계]                  ← 쓰는 곳     Ctrl + Alt + Shift + L
     미리 만들어 둔 것. 이해 못 해도 된다. 눌러서 바로 써 본다.
```

| 단계 | 내용 | 비고 |
|---|---|---|
| 0 | `MsgBox` 첫 알림창 | 나중에 도움말 버튼으로 재활용 |
| 1 | 핫키 + `Run` | |
| 2 | 런처 창 (`Gui`) | |
| 3 | 버튼 늘리기 — **버튼 하나가 두 줄** | 예전의 배열·`Bind` 방식을 빼고 나열식으로. 두 줄 복사해서 이름만 바꾼다 |
| 4~5 | 핫스트링 / 한글은 클립보드로 | |
| 6 | 일하는 버튼 (`Sleep` + `Send`) | |
| 클릭 1 | 좌표 한 곳 누르기 | Window Spy로 좌표 확인 |
| 클릭 2 | 두 곳 순서대로 | `Sleep`을 0으로 바꿔 보면 헛나가는 걸 체감 |
| 클릭 3 | 그림 찾아 누르기 (`ImageSearch`) | **강사 시연 후 따라 하기** |
| 7 | 받은 런처 써 보기 | 설명 없이 먼저 눌러 본다 |
| 8 | 목록으로 묶기 (`for`, `Bind`) | 가볍게 보고 넘어감 |
| 9 | `A_ScriptDir` — 폴더째 옮겨도 도는 이유 | |
| 10 | 덤: 창 제어 · 창 배치 · 서식 없이 복사 · 자동 도움말 | 단축키만 알려 준다 |
| 11 | 덤: 메일 상용구 (`/ad` `/sg` 등) | '내 정보' 여섯 줄만 바꾸면 전부 반영 |

각 단계는 앞 단계의 약점을 고치는 순서입니다. 특히 클릭은
**절대좌표(창 옮기면 깨짐) → 순차 클릭(Sleep 없으면 헛나감) → 그림 찾기(창이 어디 있든 맞음)** 로 이어집니다.

- 원본의 개인정보는 정리해서 넣었습니다 — 담당자 명단은 실명 대신 예시 3줄, 이모티콘은 업무에 쓸 만한 것만.

## 수업 중 챙겨 주실 것

### 설치 · 환경
- 편집기는 **VS Code**, 실행은 `Ctrl + F9`, 중지는 `Ctrl + F6`.
- 파일 첫 줄 `#Requires AutoHotkey v2.0` 이 있어야 v2로 돕니다.
- **Window Spy**: 작업표시줄 H 아이콘 우클릭 → Window Spy (또는 시작 메뉴에서 "Window Spy" 검색).
- 트레이의 "Edit Script"는 SciTE로 열립니다. 수업에선 신경 쓰지 말고 VS Code에서 여시면 됩니다.
- 공무원 PC는 설치 · 시작프로그램 등록이 막혀 있을 수 있습니다.

### 자주 막히는 곳
| 증상 | 원인 · 안내 |
|---|---|
| AI가 준 코드가 오류 | v1 문법일 가능성 큼 → **"AutoHotkey v2로"** 를 꼭 붙여서 다시 요청 |
| `::/tel::번호 ; 설명` 치면 설명까지 입력됨 | 한 줄 핫스트링은 `::` 뒤가 전부 입력 내용. 주석은 `{ }` 블록 형태에서만 |
| 한글 상용구 글자가 깨짐 | `Send`로 한글을 보내면 IME와 충돌 → 클립보드 방식(5단계) |
| `/mail` 이 한글 프로그램에선 되는데 메모장에선 뒤섞임 | 메모장(윈11)이 빠른 키 입력을 못 따라가는 것. 코드 문제 아님 |
| 경로를 모르겠다 | 파일 **Shift + 우클릭 → "경로로 복사"** |
| 버튼 눌러도 반응 없음 / 오류 | 경로 오타. 아랫부분 런처는 "어디를 고치라"고 알려 줌 |

### 클릭 3단계 (그림 찾아 누르기)
- **강사 시연을 먼저 보고 따라 하게** 해 주세요. 캡처 과정이 몇 단계라 혼자 하면 놓칩니다.
- 캡처: `Win + Shift + S` → `mspaint` → `Ctrl + V` → `Ctrl + S` (PNG) → Shift + 우클릭으로 경로 복사.
- **배경이 투명한 PNG는 절대 못 찾습니다.** 그림판으로 저장하면 안전합니다.
- **화면 배율이 다른 PC에서 만든 그림도 안 맞습니다.** 그림은 반드시 자기 PC에서 자기가 캡처.
- 오류 문구로 원인 구분:
  - `MouseMove requires a Number, but received an empty string` → **화면에서 그림을 못 찾음** (가장 흔함). 마우스가 안 움직이니 엉뚱한 곳은 안 눌립니다.
  - `Parameter #7 of ImageSearch is invalid` → **경로가 틀림**

### 아랫부분 런처
- `Ctrl + Alt + Shift + L` 로 열립니다. 2열 창(776 × 500)이라 1366×768 화면에서도 들어갑니다.
- 버튼 이름 앞에 **`PY`** 가 붙은 셋은 **안 열리는 게 정상**입니다. 파이썬이 없어서이고, 그게 숙제입니다.
- 무슨 단축키가 있는지 헷갈리면 `Ctrl + Alt + H` — 파일을 읽어 목록을 자동으로 보여 줍니다.

## 숙제로 나가는 것

1. **내 버튼 붙이기** — 아랫부분 "내가 자주 쓰는 것"에 자기 업무 버튼 추가. 막히면 코드를 통째로 AI에 붙여넣고 "버튼 하나 추가해줘".
2. **PY 버튼 살리기** — 파이썬을 깔고, 프로그램마다 필요한 걸 AI에게 물어 가며 설치해서 PY 버튼 세 개를 여는 것.
   강의 중엔 설치·환경변수가 장애물이지만 숙제로는 오히려 좋은 재료이고, AI에게 프로그램을 시킬 때 가장 잘 통하는 게 파이썬이라 한 번 깔아 두면 범위가 확 넓어집니다.
   (마트 계산기가 필요한 게 제일 적어서 첫 도전으로 좋습니다)
